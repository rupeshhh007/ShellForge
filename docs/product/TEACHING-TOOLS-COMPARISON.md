# Existing teaching tools and this project's contribution

Primary sites inspected 2026-10-22; this is a feature comparison, not a usability
study or a claim of educational superiority.

| System | Existing contribution | Relationship to ShellForge |
| --- | --- | --- |
| [Python Tutor](https://pythontutor.com/) | Stepwise execution with variables, objects, pointers and stack; explanations and next-step reasoning | Execution visualization and prediction are established teaching ideas. ShellForge specializes in bounded GNU-find and permission misconceptions, adds a computed small distinguishing fixture and scores a later transfer prediction |
| [OSTEP VizTools](https://srg-ics-uplb.github.io/cmsc125/viztools/index.html) | Interactive OS demonstrations including scheduling, memory and concurrency; scheduling can be filled one decision at a time | The existing ShellForge scheduler is not unprecedented. The new teaching contribution is the integrated prediction → deterministic trace → witness → repair → transfer loop, currently on filesystem cases |
| [explainshell](https://explainshell.com/) | Maps shell command arguments to relevant manual explanations | Forge/X-Ray anatomy builds on the established command-explanation pattern. The Almost Right Lab adds independently evaluated synthetic outcomes and a bounded search distinguishing the displayed command pair |
| [OSTEP textbook](https://pages.cs.wisc.edu/~remzi/OSTEP/) | Formal OS teaching around virtualization, concurrency and persistence | Provides the conceptual teaching context; this project's narrower filesystem models do not replace kernel semantics or textbook exercises |

Specifically implemented here: a deterministic command-derived fixture constructor,
finite cost ordering and witness certificate over declared observables; immutable
versioned prediction/action logs; independently scored transfer fixtures; and the
integration of one genuine saved LoRA prediction into an explicitly adjudicated
command-repair investigation. These combine known simulation, formative-assessment
and counterexample techniques in a project-specific product. There is no claim
that counterexamples, interpreters, visualization, prediction exercises or tutoring
were invented by this project.

Correctness tests and browser demonstrations measure software behavior. They do not
measure student learning gains, cognitive load, course marks or retention. Those
would require a separately designed participant evaluation.
